# Light Cone Wiki — семестровая работа №1

Сайт-каталог коллекционных карточек: световых конусов из Honkai: Star Rail.
Приложение написано на собственном веб-фреймворке (`MiniHttpServer.Framework`, на основе `HttpListener`),
собственном шаблонизаторе (`MiniTemplateEngine`) и собственной ORM (`MiniHttpServer.ORM`, PostgreSQL).

| Страница | Адрес | Что делает |
|---|---|---|
| Каталог | `/` | Поиск по названию, фильтры по редкости и пути, сортировка — без перезагрузки (AJAX) |
| Карточка конуса | `/cone?id=1` | Арт, характеристики на Ур. 1 / Ур. 80, эффект S1–S5, описание |
| Админка | `/admin` | Вход, CRUD конусов и путей, загрузка арта, WYSIWYG-редактор описания |

Учётные записи из начальных данных:

| Логин | Пароль | Права |
|---|---|---|
| `admin` | `Admin123` | всё, включая удаление и управление путями |
| `editor` | `Editor123` | добавление и редактирование конусов |

## Запуск в Docker (рекомендуется)

Нужен Docker Desktop. Из папки `CardsApp`:

```bash
docker compose up --build
```

- сайт: <http://localhost:8080>, админка: <http://localhost:8080/admin>;
- PostgreSQL поднимается в соседнем контейнере, `db/*.sql` выполняются автоматически при первом запуске;
- база доступна снаружи на порту `5433` (postgres / postgres);
- загруженные арты хранятся в томе `uploads` и переживают пересборку.

Остановить: `Ctrl+C` или `docker compose down`. Начать с чистой базы: `docker compose down -v`.

Сервер принимает команды из консоли (`start`, `stop`, `restart`, `exit`). В контейнере к ней можно
подключиться командой `docker attach <имя контейнера app>` (отключиться — `Ctrl+P`, `Ctrl+Q`).

## Локальный запуск

Нужны .NET SDK 10 и PostgreSQL.

1. Создайте базу и заполните её:
   ```bash
   psql -U postgres -c "CREATE DATABASE lightcones"
   psql -U postgres -d lightcones -f db/01_schema.sql -f db/02_seed.sql
   ```
2. Проверьте строку подключения в `Settings/settings.json` (по умолчанию `localhost:5432`, `postgres/postgres`).
   Её можно переопределить переменной окружения `CONNECTION_STRING`.
3. Из папки `CardsApp`:
   ```bash
   dotnet run
   ```
4. Откройте <http://localhost:8080>.

Шаблоны, статика и настройки копируются в `bin/.../` при сборке: фреймворк ищет их относительно папки с exe.
Загруженные через админку арты сохраняются в `bin/.../static/uploads`.

## Как выполнены требования

**Архитектура (MVC + Repository).** Контроллеры только принимают запрос и выбирают представление.
Логика живёт в сервисах (`CatalogService`, `LightConeAdminService`, `PathAdminService`, `AuthService`),
доступ к данным — только через репозитории (`IRepository<T>` → `OrmRepository<T>` → `IOrmContext`).
Зависимости собираются один раз в `AppServices`: фреймворк создаёт контроллеры конструктором без параметров.

**ORM и БД.** Пять таблиц со связями и ключами: `paths`, `lightcones` (FK → paths), `lightconestats`
и `superimpositions` (FK → lightcones, `ON DELETE CASCADE`), `users`. Все запросы ORM параметризованы.

**Шаблонизатор.** Каждая страница — шаблон с подстановкой `${...}`, условиями `$if/$else` и циклами `$foreach`.
Общая шапка вынесена в `Shared/_Layout.html`: `ViewResult` рендерит макет и представление и вставляет одно в другое.
Шаблонизатор экранирует все значения, поэтому описание из WYSIWYG-редактора сначала очищается
`HtmlSanitizer` (остаются только безопасные теги и http(s)-ссылки), а затем вставляется в слот `<!--raw:description-->`.

**Веб-сервер и ошибки.** Каждое действие контроллера выполняется в `SafeAsync`: любое исключение (например,
недоступная БД) превращается в страницу ошибки со ссылкой «На главную», сервер продолжает работать.
Некорректный `id` или несуществующий конус — страница 404. Неверные параметры фильтра просто игнорируются.

**Формы и валидация (клиент + сервер).** Три формы ввода: вход, конус, путь (плюс поиск в каталоге).
Регулярные выражения одинаковые в `Services/Validation.cs` и `static/js/validation.js`: логин, пароль,
название, адрес арта, ключ пути, название пути, число. Ошибки показываются под полями, введённые значения
сохраняются. Счётчики символов с ограничением длины — на текстовых полях.

**AJAX.** Каталог фильтруется через `GET /api/cones` без перезагрузки; в админке через AJAX проверяется
уникальность названия (`/api/cones/name-available`) и загружается арт (`POST /admin/upload`, тело — сам файл).

**Админка.** Вход по логину и паролю (PBKDF2-SHA256), сеанс в cookie `HttpOnly`. Права разделены:
редактор не может удалять и управлять путями (403). WYSIWYG — Quill 2 (`static/vendor/quill`).

**Вёрстка.** Чистые HTML и CSS по макету из Figma, десктоп и мобильная версия (≤ 640 px).
Шрифты Onest и Unbounded лежат локально в `static/fonts`.

## Особенности фреймворка, которые стоит знать

- Контроллеры должны лежать в пространстве имён `HttpServer.Controllers`, класс оканчивается на `Controller`,
  действия начинаются с `Process` и помечены `[Method]` и `[Route]`.
- В маршрутах нет параметров пути, поэтому карточка открывается как `/cone?id=1`.
- `responsePath` в настройках указывает на несуществующий `static/index.html`: иначе статика перехватила бы `/`,
  и каталог не отдавался бы контроллером.
- ORM выбирает только всю таблицу, поэтому фильтрация и поиск по `Id` выполняются в памяти в репозитории.
  `InsertAsync` возвращает число строк, а не `Id`: `Id` новой записи находится по уникальному полю.
